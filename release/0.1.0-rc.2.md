# 0.1.0-rc.2 development candidate

This successor is under development. It is not the immutable rc.1 source, a
final 0.1.0 release, a registry publication or a claim of completed GPU/native
acceptance. Package versions remain 0.1.0. Consult the qualification sidecar
for the exact source and software checks that have actually completed.

## Preview API migrations

- Experimental Viewport camera/projection paths remain through re-export from
  one camera owner. CPU projection/picking now follows renderer size floors and
  depth clipping, and small valid triangles remain pickable. `ViewportAction::FrameAll`
  becomes `ResetCamera`, accurately naming its existing default-camera reset;
  scene-dependent framing stays Host-owned. Remove the unused `render::RenderStats`
  placeholder; no replacement 3D statistics service is implied. Mesh/object
  packing rejects non-finite payloads, and the Vulkan failure stage changes from
  `viewport_vertex_colors` to `viewport_vertices`. Stage-matching consumers must
  migrate explicitly. [Contract and pending qualification](../docs/VIEWPORT.md).
  Numeric-label overlays now apply the anchor's near/far camera clip before
  moving glyphs to overlay depth; occlusion tolerance no longer exposes labels
  outside the camera volume. Visible placement, atlas and shader layouts remain.

- Native capture now admits the actual outward-rounded physical pixels against
  redacted visible bounds. A fractional crop beside a sensitive control can
  therefore reject with `sensitive_region`; malformed/unrepresentable geometry
  rejects with the existing `invalid_capture_region`. Precise inner crop edges
  retain the current target-size and budget conventions. Standalone uses this
  shared admission for initial/pending capture. Public signatures and wire limits
  stay unchanged; see [Native ownership](../docs/NATIVE.md).

- Core layout now uses one precise cumulative edge policy for position and
  dimensions. Negative half ties move toward positive infinity, correcting
  the previous position/size mismatch; final one-pixel rows at the admitted
  fixed-list extent remain hittable. Whole-logical-pixel quantization and
  public APIs stay unchanged. See [decision 0024](../docs/decisions/0024-Precise-Cumulative-Layout-Finalization.md).
- Widgets keep existing root exports while splitting mixed private state into
  scroll, menu, tab and popup-placement owners. Modal ID/native metadata share
  one entry; computed fixed ranges preserve the final row; foreign menu-step
  descriptors do not alter the active highlight; status partitioning recomputes
  retained width without subtractive overflow. Measured menus reject invalid
  bounds/anchor geometry with `InvalidConstraint` before adapters. See the
  [complete ownership contract](../docs/WIDGETS.md), including legacy local
  popup modes and raw-helper preconditions.

- Core re-exports the existing `Polyline` payload used by public Style data.
  CPU strokes fill bevel joins and share ordinary inner edges, with explicit
  short/reversed/self-overlap limits. Signatures and shared vertex layout remain;
  see [render preparation](../docs/RENDER-PREPARATION.md). Owner-generation
  capacity failure now preserves the previous instance/cursor/reference set;
  its legacy error code and public Result signature remain unchanged.

- Core `Size::is_valid` / `Rect::is_valid` own finite, nonnegative, representable
  logical geometry. Rectangle containment/intersection reject invalid operands;
  Image/Dock reuse that rule. Layout rejects nonfinite Style/scroll input with
  `NonFiniteStyle(element)` and invalid derived geometry with
  `InvalidGeometry(element)`. Exhaustive LayoutError matches must handle these
  cases; use `Auto`/optional constraints rather than infinity. Finite negative
  normalization, margins and zero-sized nodes remain. Scope exhaustion now
  implements standard Error for Host propagation. See
  [Core contracts](../crates/vesta-gpui/SUPPORTED-API.md#numeric-values-and-admission).

- Workspace projection returns `WorkspaceProjectionError`, replacing the unit
  `WorkspaceIdentityOverflow`; invalid/duplicate header command IDs retain their
  pane/command identities. `DockFrame::from_layout` now returns Core LayoutError
  instead of silently publishing partial geometry. Pane/split frames retain
  actual `flow_direction`; scalar split helpers require it, and
  `SplitResizeSession::new` takes the complete `DockSplitFrame`. Physical RTL
  sides/deltas map to authored order. Retire old input geometry on failure;
  migrate published-pin Hosts together. See [Dock contracts](../docs/DOCK.md).

- Workspace live state is admitted through `with_tree` or versioned session
  restore. Raw `WorkspaceModel` Deserialize and `floating_window_mut` are removed;
  use `set_floating_title` / `set_floating_placement` and handle their Results.
  `spawn_floating_window` and `set_item_type` now also return Results. Pre-seeded
  nonempty panes need an explicit valid active item. Session invariant errors
  wrap the single `WorkspaceError` cause; v1 wire data remains unchanged.
  Unreachable `EmptyWorkspace` is removed; resizing a missing container reports
  `MissingContainer`. Ordering and exhausted-ID failures now preserve complete
  model state. See [workspace contracts](../docs/WORKSPACE.md).

- `WebView.owner` was a redundant mutable copy; callbacks always retained the
  original creation tag. Retain the `ViewOwner` passed to `create` and read
  `WebEvent.owner` instead. Changing a view generation requires disposal and
  recreation; no replacement getter or second identity owner is introduced.
  Native `sync` now retains each successful hide/move/show observation when a
  later native call fails, allowing an accurate retry.
  `create` now also requires a Host-created `WebRetirement` argument. Keep this
  observation group even when creation fails, dispose children before their
  parent, and call `observe` off the live event loop before process exit. The
  existing I/O worker retires SDK temporary profiles after native locks release;
  application profiles remain Host-owned. See [the full contract](../docs/WEBVIEW.md).

- `vesta_gpui::build_editor_outline` and `demo_ids` were early demonstration
  helpers. Their implementation and fixed IDs now live in the public
  `editor_outline` example: `cargo run -p vesta-gpui --example editor_outline`.
  Applications build their own UI from Element/Style instead of importing a
  Studio demonstration page from the base library.
- Import `popup_monitor_bounds` from `vesta_gpui_winit`, replacing its former
  `vesta_gpui_vulkan` import. Its read-only placement behavior is unchanged.
  The renderer does not depend on the adapter merely for a compatibility alias.
- `ViewportScene::acceptance_scene` was a fixed experimental demonstration
  fixture. It now lives privately in Standalone's `viewport_demo` module.
  Construct a `ViewportScene` from the host's own renderables instead of importing
  fixed cube IDs, transforms and selection from the neutral library. Scene data,
  picking, camera and selection contracts are unchanged.

Text editing/shaping/view errors now implement the standard error traits; native
editing/clipboard and ellipsis wrappers retain their original causes. Existing
variants, limits, failure admission and native generic error bounds remain.
Display wording is explanatory; use typed variants rather than matching strings.
The font/cache context is private implementation behind the same public names.

## Repository maintenance

Core's [text/semantic resource contract](../docs/TEXT-AND-OBSERVATION.md) adds an
explicit preview migration. An owner absent from the complete layout retires
its platform node ID; returning pages/virtual rows get a fresh one while retaining
Core ElementId. Clipping/disablement while still present preserves identity.
Resolve platform nodes through the current window tree, never author persistence.
This removes the historical mapping accumulation without an eviction heuristic
or reusable-ID pool. Old selection-run rejection remains unchanged.

Styled shaping rejects nonfinite/nonpositive font size or unrepresentable line
height with InvalidRange. Raster paths share checked viewport/glyph preparation;
exhaustive TextRasterError matches must handle GlyphBudgetExceeded. Physical
font em, returned run and existing cache budgets are explicit, failed visitors
publish no partial callbacks, and normal work recovers after rejection. These
are accounted resource limits, not a malicious-font or whole-process sandbox.

The `native_host` Cargo example is a complete single-window editor consumer of
existing public APIs. [The recipe](../docs/HOSTING.md) documents asynchronous
GPU ownership, coherent CPU text geometry and post-loop retirement. Capability
navigation retains old contract anchors and dated evidence without adding a
framework facade or changing the two official applications.

Read-only UI condition waits now spend one shared deadline across polls and
reply waits. A condition timeout preserves the connection, while a disconnected
host reply retires it. The existing stdio launcher remains explicitly
process-lived; its callback and shutdown responsibilities are documented in
[structured UI access](../docs/AGENT-ACCESS.md), with no new public API.

An additive [in-process trace API](../docs/TRACING.md) provides bounded,
explicitly started wall-time recording shared by libraries and host scopes.
Layout/text/paint/input projection and renderer CPU phases are automatically
observed during capture; hosts own controls and export. This adds no system
profiler, telemetry upload, GPU waits or automatic GPU timestamp queries. The
native examples share `--trace-ui=<new-output.html|json>`, one frame-entry guard,
automatic parent/frame association and post-event-loop export. A shared analyzer
provides recorded call hierarchy and inclusive/self wall time per frame; the
offline report selects frames and displays these profiles. This is not automatic
tracing of every Rust/native function. The headless example produces ten CPU
attempts with real layout/text/paint calls and synthetic width steps; it does not
qualify live application latency or deploy changes to consuming products.

The native profile verifier includes all four modules and exercises accepted/
rejected evidence paths. The repository includes a pinned Windows software-check
workflow and current publication/ownership instructions. Standalone's original
window presentation/event paths and test module are split without changing their
owner, stable identities, dispatch order or acceptance assertions.

The experimental renderer successor adds Device-free production CPU preparation
and a bounded batch of disjoint scene views. Its geometry/admission and shader
software checks are separate from actual GPU rendering. See
[the rendering decision](../docs/decisions/0001-Headless-Preparation-And-Scene-Views.md)
for limits, including the explicit label edge-anchor correction.
